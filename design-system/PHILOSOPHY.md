## 1. 根本仮説：なぜ「単機能」なのか？

> **「色々できる理由がない。」**

従来のソフトウェアは、作る側の都合で巨大な「機能のデパート（メガSaaS）」へと肥大化し、ユーザーに高い学習コストと迷い、認知負荷を強いてきた。  
これからの時代に求められるのは、**「今やりたいこと1つが、1秒で、最高の手触りで終わる単機能ツール」** である。

- **ノイズの排除**: 多機能＝迷い・視界の濁り・ロードの遅延。
- **研ぎ澄まされた切れ味**: 起動した瞬間に主役があり、3ステップでゴールに届く。
- **企画意図（Why）の100%宿留**: 「誰が・何を・どうしたいのか」から逆算された唯一の解答を作る。

---

## 2. 企画意図からの逆算（Who / What / Outcome）

すべての画面・ボタン・余白は、以下の問いから冷徹に逆算される。

1. **誰が（Who）**: どんな状況・心理状態のユーザーか？
2. **何を（What）**: どんな素材・データ・入力を持ってくるか？
3. **どうしたいのか（Outcome）**: どんな成果物を手に入れて、どう終わりたいか？

この3つが定まらない限り、1行のCSSも1つのボタンも配置してはならない。

---

## 3. 主要UI と 枝葉UI の峻別

画面上の要素を「同じ強さ・同じ顔」で並べることを固く禁ずる。UIは常に**主役**と**舞台裏**に二分される。

```text
┌─────────────────────────────────────────────────────────────────┐
│  【主要UI】 (面積 85〜90%)                                      │
│  - 画面を開いた瞬間 0.1秒で視線が吸い寄せられる太い主動線       │
│  - 目的達成のための舞台そのもの（入力・プレビュー・メイン操作）   │
│  - 最大の面積、呼吸する余白、極上のタイポグラフィ               │
├─────────────────────────────────────────────────────────────────┤
│  【枝葉UI】 (面積 10〜15% / 控えめ・折りたたみ)                 │
│  - 詳細設定、微調整、例外処理、過去ログ                         │
│  - 普段は息をひそめ、必要な時だけスッと手が届く                 │
│  - 決して主要UIの邪魔をせず、視界のノイズにならない             │
└─────────────────────────────────────────────────────────────────┘
```

---

## 4. 直列遷移（Linear, One-Way Flow）

UIを行ったり来たり（反復横飛び）させる迷路構造を完全排除する。  
ユーザーは**前を向いて一本道を歩くだけで、気づいたら目的が達成されている**状態を作る。

```text
 [Step 1: 入れる] ───────> [Step 2: 整える/確認] ───────> [Step 3: 受け取る (Done)]
   (主要UIに投入)            (デフォルト最善表示)           (一撃で成果物獲得)
```

### 直列遷移の絶対原則
1. **往復ゼロ（One-Way）**: 別画面や別タブに飛ばして戻らせるモーダル地獄を作らない。
2. **迷いゼロ（Next-Action Focus）**: 目の前にあるのは常に「次の1手」だけ。
3. **戻り安心（Predictable History）**: 一本道だからこそ、いつでも安全に前の状態に戻れる。

---

## 5. 最善の初期値（Sane Defaults）と Skipボタン

ユーザーの時間を1秒たりとも奪ってはならない。

- **80点デフォルト**: 何も調整しなくても、最初からプロ品質の最善値が選ばれている。
- **明示的な Skip ボタン**: こだわりたい箇所だけ触り、不要なステップは `[ スキップして次へ → ]` で即座に飛び越える。
- **一撃の完了（Instant Done）**: 最後のステップを踏んだ瞬間に、成果物（ファイル・コピー・保存）が手に入り、スッと終われる。

---

## 6. 自然言語 E2E Snowball（仕様 ＝ テスト ＝ エビデンス）

この思想を永久に保証するため、テストはコードではなく**「ユーザーの成功ストーリー（自然言語）」**として雪だるま式（Snowball）に蓄積・実行する。

```markdown
### シナリオ例: 最速スキップ完走
1. 画面を開く
2. 原稿テキストを貼り付ける
3. 「スキップして書き出す」を押す
4. 文庫版PDFが即座に出力されること
```

- **非破壊性の保証**: UIパーツや機能を追加するたび、自然言語シナリオを末尾追記し、通し全PASS（Evidence）を確認する。
- **yui連携**: レイアウト崩れ・ボタン遮蔽・極小タップ領域・縮退がゼロであることを機械的にも同時保証する。

---

## 7. DONE（完了）の静寂Dim（明度フィルター）と焦点の刻印

作業を終えた瞬間、画面を真っ黒にするのではなく、**全体の明度を一段スッと落とすフィルター（Dim / 陰影ベール）**をかけ、舞台の照明が静かに落ちたかのように成果物だけに焦点を合わせる。

```text
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│       [ 画面全体に薄い陰影フィルター (brightness 0.9 / Dim) ]     │
│                                                                 │
│                     ┌────────────────────┐                      │
│                     │       [ 印 ]       │                      │
│                     │    組 版 完 了     │                      │
│                     │  [ 成果物を保存 ]  │                      │
│                     └────────────────────┘                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

- 黒塗りではなく、**「既存の和紙の世界観を保ったまま、明度を静かに落として中央の成果物を浮き彫りにする」** 佇まい。
- ユーザーは「完了した」という心地よい安堵感を得て、迷わず成果物を受け取れる。

## 8. 線の省略と急所の線（無駄な線を削り、要の1本を通す）

線の全廃（極端主義）ではなく、**「不要な囲み線・装飾線を削ぎ落とし、視認性と構造に必要な【急所の線】を端正に通す」**。

```text
【不要な線（削る）】                     【急所の線（端正に通す）】
- 全体を無意味に囲む外枠の檻              - 入力領域・触れる場所を示す静かな1px境界
- 余白で自明な箇所の多重デバイダー        - データ表や比較の可読性を保つ微細な水平線
- ボタンやタグの過剰な四方ボーダー        - 引用・プレビューの背骨となる縦線 / 朱の帯
                                        - フォーカス・エラー・処理中ドットの境界
```

### 線の配置基準（使うべきところ、引くべきところ）
1. **触れる場所（Affordance）**: 入力欄やドロップ領域には、迷わせないための端正な 1px（`#DDD9D0` / 控えめな境界）を通す。
2. **情報の誤読防止（Data Clarity）**: テーブルや比較リストなど、線がないと行が混ざる場所には静かに水平線を敷く。
3. **主動線の背骨（Spine）**: プレビューの左端の朱線や、直列パイプラインの進行など、構造の芯となる1本を美しく通す。
4. **過剰な装飾の排除**: 「とりあえず四方を線で囲む」「カードの周りに太い枠を付ける」といったノイズだけを冷徹に削る。



## 9. 左右 HUD：ボタンと物理キーの対応表（常時佇む案内）

プロフェッショナルな道具として、**「ボタン ＋ 物理キー」の対応表が左右（または端部）に控えめ（小さめ）に常時佇む**。

```text
【左HUD: ナビゲーション】              【右HUD: 主要アクション】
 [Esc]    戻る                         [⌘+↵]   次へ進む / 完了
 [Space]  スキップ                     [⌘+S]   ダウンロード
```

- マウス操作派にもキーボード派にも、**「次にどのキーを押せば最速で終わるか」**が常に視界の隅に小さく寄り添う。
- 認知負荷を増やさないよう、文字サイズは `11〜13px`、控えめなグレー（`--text-muted`）で端正に配置する。


## 10. 処理中の佇まい：Marching Dotted Frame（静かな周回表現）

野暮ったい巨大スピナーを画面中央に回すのをやめ、**「処理中のカード・枠線そのものが、5pxドットの点線となって静かに巡る（Marching Dotted Frame）」** 佇まいを採用する。

```text
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  [ 処理中... ]
  原稿を解析し、フィボナッチ組版を適用しています
  ●  ○  ○  （5pxの丸いドットが枠線上を静かに周回する）
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

- **5px 丸ドット & ゆったりとした間隔**:
  - 直径 4〜5px の美しい丸ドットが、程よい間隔（12〜16px）を空けて枠線を巡る。
- **作業領域の文脈を壊さない**:
  - 全画面を遮断（オーバーレイ）せず、処理を行っている「そのカード」だけが点線枠に包まれて思考する。
  - ユーザーは「いま何が処理されているか」が一目でわかり、安心感を得る。


## 11. エラーと危険操作の物理的伝達（Shake / Red Tint / 警告Tooltip）

ユーザーを小難しいエラー文章やモーダルで邪魔せず、**物理的な手触りと色の変化（Tint）**で直感的に伝える。

```text
┌─────────────────────────────────────────────────────────────────┐
│  ① エラー発生時   : 対象要素を微細に【振動（Shake）】＋【赤Tint】 │
│  ② 危険なUI (破棄): 赤（朱）を纏い、ホバー時に【警告Tooltip】表示 │
│  ③ インライン解決 : その場ですぐ直せる修正ヒントを添える         │
└─────────────────────────────────────────────────────────────────┘
```

### ① 微細な振動（Shake Animation）
- 入力エラーやバリデーション失敗時、ダイアログを新規で出さず、**対象の入力枠やカード自体が「カチッ」と微小に左右に震える**（200ms）。
- 物理的な手応えで「そこが通らない」ことを指先に伝える。

### ② 赤のTint（Red Tint & Border）
- モノトーン基調だからこそ、エラー箇所にうっすらとした朱のベール（`rgba(217, 56, 30, 0.08)`）と朱のボーダー（`#D9381E`）が敷かれることで、視線が迷わず問題箇所に吸い寄せられる。

### ③ 危険な操作（Destructive Action）とホバー警告
- 「全削除」「破棄」「リセット」などの不可逆なアクションは、最初から**危険色（赤/朱）のボタン・アウトライン**で明示。
- マウスホバー（またはフォーカス）した瞬間に、**「⚠️ この操作は取り消せません（原稿が消去されます）」** といった警告ツールチップ/バッジがフワッと浮き出る。
- 不意の誤操作を0.1秒の手前で確実に防ぐ。


## 12. 用の美：モノトーン基調・フィボナッチ・伝統素材の品格

美しさと実用性を極限まで高めるため、装飾のためのデザインを排し、**「用の美」**を備えた伝統的マテリアルと黄金比率で構成する。

```text
┌─────────────────────────────────────────────────────────────────┐
│  基調（95%） : モノトーン（黒・白・グレー） ── 道具としての静寂 │
│  比率        : フィボナッチ数列（1, 2, 3, 5, 8, 13, 21, 34, 55） │
│  差し色（5%）: 【原則1色】朱色 / 藍（インディゴ） / 金（ゴールド） │
│  質感        : 伝統素材（墨、和紙、漆、真鍮、石）の佇まい       │
└─────────────────────────────────────────────────────────────────┘
```

### ① 基調：白・黒・グレー（無彩色の静寂）
- UIは「コンテンツと主役（思考・原稿・データ）」を邪魔してはならない。
- 墨のような深い黒（`#121212`）、静かな背景白・紙色（`#F9FAFB` / `#F5F3EF`）、陰影を分かつ階層グレー。
- コントラスト比 7:1 以上（WCAG AAA 準拠）を保ち、視認性を極める。

### ② フィボナッチ比率（Fibonacci Proportion）
余白（Spacing）・タイポグラフィ（Type Scale）・UIの分割比率をすべて**フィボナッチ数列**で律する。

- **余白スケール (px)**:
  - `sp-1` (1px), `sp-2` (2px), `sp-3` (3px), `sp-5` (5px), `sp-8` (8px), `sp-13` (13px), `sp-21` (21px), `sp-34` (34px), `sp-55` (55px), `sp-89` (89px)
- **文字スケール (px / rem)**:
  - 注記 `13px` → 本文 `16px` → 小見出し `21px` → 中見出し `34px` → 大見出し `55px`
- **画面分割**: 主要UI（89%） : 枝葉UI（13% or 21%）の黄金分割。

### ③ 差し色（アクセント）：原則「1色のみ」
画面の中に色を散らさない。主要な決断・完了ボタン（Done）・現在地にだけ、選び抜いた**1色の伝統色**を差す。

- **朱（Vermilion / `#E23636` or `#D9381E`）**: 決断・実行・最も重要な主動線（捺印・朱入れの直感）
- **藍（Indigo / `#1E3A8A` or `#1E293B`）**: 信頼・静謐・知的作業・深奥
- **金（Gold / 真鍮・`#C5A059` or `#D97706`）**: 格調・完成・ハイライト・永続

### ④ 伝統素材のテクスチャと陰影
- ペラペラなプラスチックUIではなく、**紙の重み、墨の切れ味、真鍮の光沢、漆の沈み**を感じる微細なボーダーとシャドウ。
- 光と影の境界線をミニマルな 1px 線と鈍いトーンで制御し、画面全体に「重厚で信頼できる道具」の品格を与える。


## 13. AI が自走するときの思考順序（この思想を使うとき）

AI（自分）がWebアプリを設計・実装するときは、必ず以下の思考順序で自走する。

1. **企画意図を1行で定義する**: 「このアプリは［誰］が［何］を［どうする］ための単機能ツールである」
2. **直列ステップ（2〜3歩）を決める**: `Input → Preview/Adjust → Output`
3. **主要UIを画面中央にドンと置く**: 枝葉は隅・控えめ・折りたたみに逃がす
4. **最善の初期値とSkipを用意する**: ユーザーに入力を強制しない
5. **自然言語E2Eシナリオを snowball に書く**: 企画意図通りの体験が完走できることを実証する
