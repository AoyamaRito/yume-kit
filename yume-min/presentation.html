yume-min

AIがコードを「読んで・編集して・履歴を残す」ための最小実装。
1ファイル一気読みできる、けずり切ったコア。
「AIは建築家であり、人間は監督である。」—— V4.3
Total 737行（core.jsはわずか218行）／ テスト 31件全グリーン
WHY — なぜいま、これを

つくった理由

01

AIはgitの履歴を見られない

履歴は.gitの中にあって、ファイルを開いただけでは見えない。AIには「今の内容」しか残らない。→ 履歴を平文でファイルに内蔵する。

02

並列は品質を下げる

1つの状態を複数AIで分けると、名前・構造の一貫性が失われ、それを補修する装置が更に複雑さを招く。

03

激安AIなら単一で十分

1体を延々回してもコストは気にならない。並列の「スピード」という報酬はもう要らない。

DETAIL — コア設計

Block / expand / apply

Block

実体 + 履歴

id / type / versions[]。append-only で直近32版キャップ。content は head から派生（= 状態は1本）。

apply の安全

ヘッダ整合 + 原子性

hash境界の改ざん・ID不一致を検知してアトミックに拒否。本文だけを安全に戻す。

// >>> BLOCK mod:fn:add type=function hash=abcdef12
// …… 本文 ……
function add(a, b) { return a + b; }
// <<< /BLOCK mod:fn:add hash=abcdef12
DETAIL — 全語言語の往復

lift.js — エンブレム方式

言語パーサ（JS限定）は持たない。マーカーはコメント行だから、どの言語でも同じ境界が使える。

JS

// マーカー

// >>> BLOCK … 本文 … // <<< /BLOCK

Python

# マーカー

# >>> BLOCK … 本文 … # <<< /BLOCK

const { graph, spans } = lift(src);        // 実ファイル → 正本Graph
const view  = expand(graph, root);          // 単一AIが厚ビューで編集
apply(graph, root, edited);                 // 新バージョンを append
const out   = render(src, graph, spans);    // 更新した本文で実ファイルを再構築
DETAIL — 平文履歴

persist.js — git に頼らない

人間はAIにgitの権限を渡さないことが多く、gitは気軽に扱うものでもない。
→ 履歴込みのGraphを平文 JSONとして保存。そのままgrep / AIが読める。

保存

save(graph, file)

versions（直近32版）を含む平文JSONを出力。git操作ゼロ。

復元

load(file)

最新版だけでなく過去版もそのまま復元できる。

「今の内容」は残っても「なぜこうなったか」が失われる問題を、ファイル形式側で防ぐ。
DETAIL — 検証の目

cover.js — ホワイトボックスの目

単一AIが長時間まわすとき、「テストは通った」だけでは足りない。「どの行がまだ実行されていないか」まで見えるべき。

実行

runWithCoverage(fn, url)

V8精密カバレッジで対象ファイルの関数/区間を収集。

指摘

analyzeCoverageGaps(fn, src)

実行されなかった「意味のある区間」だけをgapsとして抽出。

e2eの「ついでに育てる」を、自動で穴を指摘する形に強化する。
DETAIL — けずったもの

「なにを積まないか」こそ本質

切った装置切った理由
並列化（YVCP / v00x / 契約キー）軌跡の根っこに無い。単一激安AIに不要。品質を下げる
stale-write 検知並行変更の上書き防止＝並列前提のガード。単一作者に無用
言語パーサ（parseJS等）JS限定・重い・構造をファイルから引き剥がす
makeThickEdit/applyThickEditremote/並列の通信素管。単一コアに不要
crystallize / go-kernel別方向の重装備。ネイティブ化はオーバーキル
